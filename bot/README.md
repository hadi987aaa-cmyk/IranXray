# ربات مدیریت کاربر Shaghali — نصب‌کنندهٔ خودکار

اسکریپتی که روی هر سرور تازه، بعد از نصب Xray (مثلاً با `v2ray-agent`)، ربات تلگرام مدیریت کاربر
را نصب می‌کند و **خودش را با پروتکل و کانفیگی که فعال کرده‌اید تطبیق می‌دهد**.

## پیش‌نیاز

- Ubuntu/Debian با `python3` (روی نسخه‌های ۲۰ به بعد از پیش نصب است).
- Xray نصب‌شده و **حداقل یک inbound از نوع VLESS / VMess / Trojan با کلاینت**.
- توکن ربات از [@BotFather](https://t.me/BotFather).

اسکریپت به `v2ray-agent` وابسته نیست؛ هر نصب دیگری هم که ساختار JSON استاندارد Xray داشته باشد
شناسایی می‌شود. اگر `v2ray-agent` باشد، در گزارش می‌نویسد «detected».

## نصب (یک دستور)

```bash
curl -fsSL https://raw.githubusercontent.com/hadi987aaa-cmyk/IranXray/bot/host/bot/shaghali-bot-install.py \
  -o /root/setup.py && python3 /root/setup.py
```

اسکریپت توکن را می‌پرسد، سپس می‌گوید «در تلگرام ربات را باز کنید و /start بزنید» و خودش
`chat id` شما را پیدا و ذخیره می‌کند. تمام.

### اگر می‌خواهید اول ببینید چه چیزی پیدا می‌شود

```bash
python3 /root/setup.py --check
```

هیچ فایلی نوشته نمی‌شود؛ فقط مسیر کانفیگ، باینری xray، پورت API و فهرست inbound‌ها را چاپ می‌کند.

## اسکریپت چه کارهایی می‌کند

1. **تشخیص**: مسیر کانفیگ Xray (بین `/etc/v2ray-agent/xray/conf`، `/usr/local/etc/xray`، …)،
   باینری `xray`، و پورت API آمار.
2. **کشف inbound‌ها**: همهٔ inbound‌های VLESS/VMess/Trojan که کلاینت دارند، با tag، پورت، شبکه و
   امنیت؛ نتیجه در `inbounds.json` نوشته می‌شود و ربات از همان می‌خواند.
3. **فعال‌کردن آمار (در صورت نبود)**: فایل `99_shaghali_api.json` را با `api` + `stats` + `policy`
   می‌سازد (روی `127.0.0.1:10085`)، از کانفیگ قبلی در `/root/xray-conf-backup-<تاریخ>` بکاپ
   می‌گیرد و xray را ری‌استارت می‌کند. بدون این بخش، ربات کاربر اضافه می‌کند ولی مصرف/سهمیه را
   نمی‌تواند بخواند.
4. **نصب ربات**: محیط مجازی، `python-telegram-bot==21.6`، کپی `bot.py`، نوشتن `.env` با دسترسی ۶۰۰.
5. **سرویس systemd** `shaghali-bot` با ری‌استارت خودکار.
6. **تست پایانی**: وضعیت xray و ربات، پاسخ‌دادن API آمار، و نسخهٔ کتابخانهٔ تلگرام.

## دستورهای روزمره

```bash
systemctl status shaghali-bot
journalctl -u shaghali-bot -n 40 --no-pager
python3 /root/setup.py --check        # فقط گزارش
python3 /root/setup.py --uninstall    # حذف سرویس
```

## ارتقا

همان دستور نصب را دوباره اجرا کنید. `bot.py` و `inbounds.json` بازنویسی می‌شوند، ولی
`data.db` (کاربران، مصرف، سهمیه) و `.env` دست‌نخورده می‌مانند. اگر توکن را عوض کرده‌اید،
`--token` را بدهید یا در پرسش، توکن تازه را وارد کنید.

## چه چیزی به‌روز می‌شود در ربات

- پشتیبانی از **چند inbound** در یک سرور: هنگام «افزودن کاربر»، خودتان انتخاب می‌کنید.
- لینک اشتراک برای **VLESS** (tcp/reality، xhttp، grpc، ws)، **VMess** و **Trojan** ساخته می‌شود.
- `pbk` ریالیتی **از `privateKey` خودِ کانفیگ محاسبه می‌شود** (X25519)، پس هیچ‌وقت دستی نمی‌شود.
- فایل‌های کانفیگ بر اساس **tag** پیدا می‌شوند، نه با «اولین inbound فایل»؛ چند inbound در یک فایل
  هم مشکلی نیست.
- کلاینت Trojan با `password` ساخته می‌شود، نه `id`.

## امنیت

- `.env` با دسترسی ۶۰۰ نوشته می‌شود؛ توکن را در چت یا فایل بکاپ عمومی نگذارید.
- اگر توکن قدیمی جایی لو رفته، در BotFather `/revoke` بزنید و دوباره نصب کنید.
- ربات برای ری‌استارت xray به root نیاز دارد؛ بعد از نصب، ورود SSH را به کلید محدود کنید و
  پورت ۲۲ را با fail2ban/ufw سخت‌تر کنید.

## محدودیت‌های صادقانه

- اگر API آمار در دسترس نباشد (پورت بسته یا xray بدون `stats`)، ربات کاربر اضافه می‌کند ولی
  مصرف و سهمیه را نمی‌بیند؛ اسکریپت این حالت را در تست پایانی هشدار می‌دهد.
- **Shadowsocks** پشتیبانی نمی‌شود؛ برای آن نوع، لینک ساخته نمی‌شود.
- سهمیه یک‌طرفه است: وقتی `used_bytes` از `quota_bytes` بگذرد کاربر غیرفعال می‌شود؛ تاریخ انقضا
  ندارد (طبق درخواست خودتان).

## تست‌هایی که روی همین کد اجرا شده

`test/run_tests.py` با یک درخت کانفیگ ساختگی شبیه `v2ray-agent` (پنج inbound، از جمله دو inbound
در یک فایل) اجرا می‌شود و **۴۱ بررسی** را پاس می‌کند: کشف inbound‌ها، پیدا کردن با tag، خواندن
کلاینت‌ها، ساخت لینک برای هر پروتکل، محاسبهٔ `pbk` با بردار تست RFC 7748، نوشتن امن کانفیگ با
بکاپ، و شکل کلاینت به‌ازای پروتکل.
